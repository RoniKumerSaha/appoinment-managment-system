# Page 01.2 — Branch Picker

**Scenario:** 01 — Patient Books an Appointment
**Persona:** Maya (Patient)
**Position in flow:** Step 2

---

## Purpose

Show the patient which branches the selected doctor works at. Pick one.

## Exit action

Tap a branch → `01.3-appointment-type-picker/` (doctor and branch both pre-selected).

## Components

| Component | Notes |
|---|---|
| Back arrow | Returns to doctor list, no state loss. |
| Doctor summary | Name + specialty, fixed at top so context doesn't shift. |
| Branch card | Name, address, distance (if location permission granted), hours this week, tap-through. |
| Distance | Optional, only if geolocation granted. Otherwise hidden. |

## Behavioral notes

- **Only branches where the selected doctor works are shown.** (BR-016: appointment types offered by a doctor are bookable at every branch where they work, so the doctor-branch mapping is the gate.)
- **Operating hours this week are shown** so the patient can pick a branch with hours that suit them. This is informational, not interactive — actual slot availability shows in the slot picker.
- **Address and distance** are informational. Maps integration is out of scope; the address is enough.

## Empty / error states

| State | UI |
|---|---|
| Doctor works at zero branches (data integrity violation) | "This doctor has no branch assignments. Please pick another doctor." (Should not occur in practice; surfaced for safety.) |

## Accessibility

- Cards keyboard-navigable; distance text has sr-only label.
- Hours table uses semantic markup for screen readers.

## Mobile vs desktop

Mobile: full-width cards, vertical stack. Desktop: same — branches rarely exceed 4 in MVP; vertical stack works at all widths.
