# Page 01.1 — Doctor List

**Scenario:** 01 — Patient Books an Appointment
**Persona:** Maya (Patient)
**Position in flow:** Entry point

---

## Purpose

Show the patient which doctors she can book with. Answer "who can I see?" before she has to commit to anything.

## Exit action

Tap a doctor → `01.2-branch-picker/` (branch pre-filtered to branches where the doctor works).

## Components

| Component | Notes |
|---|---|
| Header | Clinic name + help icon (?). Help opens a one-screen explainer: phone is identity, OTP for return visits, no account needed. |
| Page title | "Book an appointment." Subtitle: "Pick a doctor to start." |
| Search field | Filters the doctor list by name. Real-time. Mobile-first keyboard. |
| Doctor card | Avatar/initials, name, specialty, branch count, optional one-line bio, "Book →" button. |
| Returning patient link | "Already booked? View your appointments." Bottom of page. Goes to OTP gate (1.7). |

## Behavioral notes

- **Search by name only.** Specialty search, location search, symptom search are out of MVP scope.
- **Inactive doctors are hidden.** A doctor without active appointment types is not bookable; do not show.
- **No filter chips** (specialty, language, gender) in MVP. Can be added in Phase 8 (Evolution) based on usage.
- **Doctor cards are tap-through.** Whole card is the action; the explicit "Book →" button is the affordance.

## Empty / error states

| State | UI |
|---|---|
| No doctors in the system (clinic misconfigured) | "No doctors available right now. Please call the clinic." |
| Search has no results | "No doctors match. Try a different name." |
| Network error | "Couldn't load doctors. [Try again]" |

## Accessibility

- All cards keyboard-navigable.
- Search field has visible label and aria-described help text.
- Color contrast on doctor cards meets WCAG AA.
- "Book →" button is focusable with visible focus ring.

## Mobile vs desktop

Mobile: cards stack full-width, one column. Desktop: cards in a two-column grid up to 800px wide, then stack.
