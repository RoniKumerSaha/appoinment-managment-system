# Page 01.7 — OTP Verification

**Scenario:** 01 — Patient Books an Appointment (also reused for any patient return)
**Persona:** Maya (Patient)
**Position in flow:** Gate to the patient dashboard

---

## Purpose

Verify the patient's phone number so she can see her appointments. This is the *only* authentication path for patients in MVP (BR-029 / FR-031).

## Exit action

Enter correct OTP → `01.8-patient-dashboard/`.

## Components

| Component | Notes |
|---|---|
| Back arrow | Returns to wherever she came from (confirmation, or external entry). |
| Title | "View your appointments." |
| Phone display | Partially masked. |
| OTP input | 6 separate boxes, auto-advance, paste support, numeric only. Mobile-first keyboard. |
| Resend button | Cooldown timer (e.g., 30 seconds). Disabled while timer running. |
| Different number | Replaces the phone field. New OTP sent. |
| Phone-call fallback | For NG-P3: "Lost access to this phone? Call the clinic." |

## Behavioral notes

- **OTP length is fixed at 6 digits** for MVP. Configurable OTP length is out of scope.
- **Cooldown on resend** prevents abuse (PRD implies OTP infrastructure is available; assume standard rate limits).
- **Attempt limit** (PRD implies): after N failed attempts, the OTP is invalidated and the patient must request a new one.
- **Auto-submit on 6 digits** — no separate "Verify" button. The patient types, the system verifies.
- **Paste support** — clipboard paste fills all boxes.
- **Phone-call fallback is intentional.** NG-P3: "I can't get my OTP." The path is "call the clinic," not "create an account."

## Empty / error states

| State | UI |
|---|---|
| OTP incomplete | No submit until 6 digits entered. |
| OTP wrong | "Wrong code. Try again." Boxes clear. |
| OTP expired | "Code expired. [Send a new code]" |
| Too many failed attempts | "Too many attempts. [Send a new code]" |
| Resend cooldown | Button disabled with timer. |
| SMS delivery failure | "Couldn't send the code. [Try again]" |
| Phone number not recognized | "We don't have any appointments for this number yet. [Book an appointment →]" |

## Accessibility

- OTP boxes are inputs, not divs.
- Paste from clipboard is keyboard-accessible.
- Errors announced via aria-live="polite".
- Visible focus on the active input box.

## Mobile vs desktop

Mobile: full-width OTP boxes, numeric keyboard. Desktop: centered max-width 400px.

## Security notes

- OTP rate limit per phone number (e.g., 5 attempts per hour).
- OTP TTL: 5–10 minutes.
- OTP not logged client-side.
- HTTPS only.
