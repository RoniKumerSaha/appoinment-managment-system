# Page 01.3 — Appointment Type Picker

**Scenario:** 01 — Patient Books an Appointment
**Persona:** Maya (Patient)
**Position in flow:** Step 3

---

## Purpose

Let the patient pick what kind of visit she wants, with duration visible (so she knows what she's committing to).

## Exit action

Tap a type → `01.4-slot-picker/` (doctor, branch, type all pre-selected).

## Components

| Component | Notes |
|---|---|
| Back arrow | Returns to branch picker. |
| Context bar | Doctor + branch, fixed at top. The patient doesn't lose track of where she is. |
| Type card | Duration is the lead (because that's what affects her day), then a one-line description. |

## Behavioral notes

- **Only active appointment types are shown** (FR-006: inactive types are not bookable at any branch the doctor works at).
- **Duration is the most prominent field.** "30 minutes" before "follow-up" — the patient is booking *time*.
- **No price field.** Billing is out of scope (BRD §2.2).
- **Description is one line, doctor-authored.** Long descriptions move to the doctor's profile (out of MVP).

## Empty / error states

| State | UI |
|---|---|
| Doctor has zero active appointment types (data integrity violation) | "This doctor has no bookable appointment types yet. Please pick another doctor." |

## Accessibility

- Duration is in a semantic `<time>` element.
- Cards are buttons with full-card hit areas.

## Mobile vs desktop

Same pattern. Vertical stack at all widths.
