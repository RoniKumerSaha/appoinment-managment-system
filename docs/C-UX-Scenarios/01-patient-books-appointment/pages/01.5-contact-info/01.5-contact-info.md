# Page 01.5 — Contact Info

**Scenario:** 01 — Patient Books an Appointment
**Persona:** Maya (Patient)
**Position in flow:** Step 5 — the moment of atomic truth

---

## Purpose

Collect the patient's name and phone number. Identify her (returning vs new). On submit, atomically reserve the slot and create the appointment.

## Exit action

Submit → atomic reservation → `01.6-confirmation/`.

If atomic reservation fails (slot taken by someone else in the last 30 seconds) → in-place error with re-pick button → returns to `01.4-slot-picker/` with the day pre-selected.

## Components

| Component | Notes |
|---|---|
| Booking summary card | Doctor, branch, type, date, time. "Change →" returns to slot picker; everything else preserved. |
| Name field | Pre-filled if returning patient (BR-027). Editable. |
| Phone field | Country code prefix. Mobile keyboard (numeric). |
| Returning-patient hint | When a phone is recognized, the stored name is suggested and a small "We've seen you before" indicator appears. |
| Phone-as-identity warning | The NG-P5 edge case surfaced explicitly. Not hidden in a help icon. |
| Confirm button | Disabled until both fields are valid. Single primary action. |

## Behavioral notes

- **Returning patient** (BR-027): as the patient types a known phone number, the stored name is shown with the option to edit. The button label is unchanged ("Confirm booking"); the behavior just gets smarter.
- **New patient**: the name field is empty; phone field is empty.
- **Phone validation**: country-code-aware, prevents obvious typos. Not strict international validation — accept reasonable input.
- **Atomic reservation** happens at submit. The submit button is disabled while the request is in flight. On success, redirect to confirmation (1.6). On failure (slot taken), show in-place error with re-pick button.
- **Auto-fill on returning patient**: name can be edited. The system *suggests*; the patient *decides*.

## Empty / error states

| State | UI |
|---|---|
| Both fields empty | Confirm button disabled. |
| Name empty, phone present | Confirm button disabled; "Please enter your name." |
| Phone empty, name present | Confirm button disabled; "Please enter your phone." |
| Phone invalid | "Please enter a valid phone number." |
| Submit in flight | Button shows spinner; "Reserving your slot..." |
| Atomic reservation fails | Red banner above the form: "This slot was just taken by someone else. [Pick another time →]" (returns to slot picker with day pre-selected). The booking is *not* created. |
| Patient conflict (already verified post-atomic-reservation) | "You already have an appointment at this time. [Pick another time →]" |
| Same-doctor future appointment (BR-031) | "You already have a future appointment with Dr. Ahmed on Aug 22 at 10:00. You can have only one upcoming appointment per doctor. [Pick another time →]" |
| Booking outside branch operating hours (BR-013) | Should not happen — the slot picker already enforces this. If it does, "This time is outside the branch's operating hours. [Pick another time →]" |

## Accessibility

- Phone field uses input type="tel" with inputmode="numeric".
- Errors are announced through aria-live="polite".
- Form labels are associated with inputs.
- Confirm button is a real `<button type="submit">`.

## Mobile vs desktop

Mobile: full-width fields, confirm button full-width at the bottom (thumb-reach). Desktop: max-width 480px centered.

## Security / privacy note

Phone numbers are sensitive. The form must:
- Use HTTPS only.
- Not log phone numbers in client-side error trackers.
- Auto-clear the form on session timeout.

## Performance note

Submit must complete in < 1 second for the typical case. Atomic reservation is a single DB transaction — see PRD §10 booking transaction sequence.
