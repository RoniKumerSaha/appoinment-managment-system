+## Intent
+
+**Problem:** E0-S3 left `/patient/otp/verify-now` as a **mocked** OTP check (`code === process.env.MOCK_OTP_CODE`). The architecture spine (Architecture §3.8 — Identity & Access: OTP) and PRD FR-031 require a real SMS-backed OTP gateway that:
+
+1. Persists issued OTPs (so they survive a server restart) with a 5-minute TTL, a 3-attempts-per-10-minute lockout, and a 30-second resend cooldown.
+2. Persists attempt counts so a brute-force probe is rate-limited at the DB layer (not just in memory).
+3. Surfaces a swappable provider interface so dev/test runs use a console-log stub and prod runs use a real SMS provider (Twilio in scope; the interface must be open).
+4. **Hashes** stored OTP codes with pgcrypto's `digest(...)` so a DB compromise does not leak live OTPs.
+5. Plays cleanly with E0-S3's minted patient JWT — the verify path produces the same `{token, claim, expires_at}` shape so E4-S1 can swap its body without rewriting the response contract.
+
+E0-S4 ships the gateway + a real `/patient/otp/send` route + a real `/patient/otp/verify` route. The mocked `/patient/otp/verify-now` is **removed** (delegated route file removed; the allowlist in `loadAuthConfig().mockOtpAllowed` becomes obsolete — the route registration in `app.ts` is gated on `NODE_ENV ∈ {development, test}` instead, OR the mock route stays for the duration of this story and is deleted in a follow-up. See "Ask First" — A1.)
+
+**Approach:** A `SmsOtpProvider` interface with two implementations: `LogSmsOtpProvider` (dev/test; emits the OTP code to the structured logger at `info` level) and `TwilioSmsOtpProvider` (prod; imports `twilio` lazily so the dev install does not require a Twilio account; failure modes surface as `SmsSendFailed`). A `SmsOtpService` wraps the provider and the DB: it generates a 6-digit numeric OTP, hashes it via `pgcrypto.digest(...)` (sha-256 in `hex` encoding → 64-char hex string, well inside the `BETWEEN 32 AND 256` CHECK on `code_hash`), inserts an `otp_verification` row inside a `BEGIN/COMMIT` transaction, and exposes `send(phone)` + `verify(phone, code)` + `attemptCount(phone)` + `remainingCooldownMs(phone)`. The verify path runs inside a transaction: it locks the `otp_verification` row with `SELECT … FOR UPDATE` (prevents two parallel verify requests both decrementing `attempts`), recomputes the hash, `timingSafeEqual`-compares, increments `attempts` on failure, sets `locked_until` when the 3-attempt threshold is hit, deletes the row on success. The 30-second resend cooldown is enforced in `send()` via a `SELECT MAX(created_at) FROM otp_verification WHERE phone_e164 = $1 AND created_at > now() - INTERVAL '30 seconds'` — if a recent row exists, return a structured cooldown error to the caller. Route handlers translate service errors into HTTP envelopes (`429` for cooldown, `429` for locked, `401` for invalid-code, `502` for provider failure).
+
+**Out of scope (deferred):**
+- Real Twilio wire-up (E1 or beyond — this story ships the interface + Twilio client class but does not require Twilio credentials at boot).
+- Web modal UI for the OTP flow (E4-S1).
+- Synthetic `patient.id` UUID for `sub` (W13 — E4-S1 owns).
+- Logout / denylist (W9 — E7 hardening).
+- Refresh tokens (W8 — E7 hardening).

+## Boundaries & Constraints
+
+**Always:**
+- `SmsOtpProvider` interface is the only seam between the service and the outside world. The service never imports `twilio` directly. The interface is:
+  ```ts
+  interface SmsOtpProvider {
+    send(phone: string, code: string): Promise<void>;  // throws SmsSendFailed on failure
+  }
+  ```
+- Two providers ship in this story: `LogSmsOtpProvider` (writes `{event: 'mock_otp_send', phone, code}` to the structured logger — replaces the old `mock_otp_attempt` log family with a `mock_otp_send` family since the surface is now a real send) and `TwilioSmsOtpProvider` (real Twilio client; constructed lazily). Selection is process-level via `OTP_PROVIDER` env var (`'log'` or `'twilio'`; default `'log'` in non-prod, `'twilio'` in prod).
+- `LogSmsOtpProvider` emits the OTP code to logs at `info` level — this is intentional dev/test behavior. Production guard: when `OTP_PROVIDER=log` AND `NODE_ENV === 'production'`, the service refuses to start (logs `otp_provider_log_in_production` and throws). Same posture as E0-S3's mock-route production guard.
+- Real Twilio is wired but **dormant** in this story: `TwilioSmsOtpProvider` is exported and exercised by a unit test that mocks `twilio` via dependency injection (the constructor accepts an optional `client` parameter; tests inject a stub). No live Twilio HTTP calls during the test suite. Twilio credentials are NOT required in `.env.example`.
+- `code_hash` uses `pgcrypto.digest(code, 'sha256')` producing a 64-char hex string. The `code_hash` column's `CHECK (length(code_hash) BETWEEN 32 AND 256)` already accepts this (verified in E0-S2). Plain OTP codes are NEVER stored — verified by `apps/api/test/sms-otp.test.ts` which inspects every column of an inserted row and asserts `code_hash` is not the raw code.
+- `send()` uses an explicit `BEGIN/COMMIT` transaction: cleanup of expired rows (rows with `expires_at < now()`) is done in the same transaction as the insert, so a leftover row from a previous send can never block a fresh send. The cleanup is `DELETE FROM otp_verification WHERE phone_e164 = $1 AND expires_at < now()` (UNIQUE on `phone_e164` means at most one outstanding row per phone; the cleanup is defense-in-depth so the UNIQUE never fires spuriously).
+- The 5-minute TTL is enforced via `expires_at = now() + INTERVAL '5 minutes'` at INSERT time. The verify path rejects `now() > expires_at` with `401 {error: 'otp_expired'}` — same status as wrong code (no oracle for "code was right but expired").
+- The 3-attempt cap is enforced via `attempts >= 3` AFTER incrementing on failure. When the cap is reached, `locked_until = now() + INTERVAL '10 minutes'`. The `send()` path checks `locked_until > now()` and returns `429 {error: 'otp_locked', retry_after_ms}` if the row is locked (lockout spans sends AND verifies — both refuse until `locked_until`).
+- The 30-second resend cooldown is enforced in `send()` via `SELECT MAX(created_at) FROM otp_verification WHERE phone_e164 = $1 AND created_at > now() - INTERVAL '30 seconds'`. If a row is within 30 seconds, `send()` returns `429 {error: 'otp_cooldown', retry_after_ms}` (computed from the row's `created_at + 30s - now()`).
+- Phone validation: `^\+[1-9]\d{6,14}$` (E.164; same regex as E0-S3's patient-otp route). The route rejects non-string / non-E.164 phones with `400 {error: 'invalid_phone'}` BEFORE consulting the service.
+- Code validation: `^\d{6}$` (exactly 6 digits). The route rejects non-string / non-matching codes with `400 {error: 'invalid_code'}` BEFORE consulting the service.
+- The verify path locks the row with `SELECT … FOR UPDATE` (in a transaction) — two parallel verify requests cannot both decrement `attempts`. The losing request blocks until the winner commits, then sees the updated state.
+- Constant-time hash comparison: the verify path computes `pgcrypto.digest(input, 'sha256')` and compares to the stored `code_hash` via `crypto.timingSafeEqual` on equal-length `Buffer`s (both 64 chars hex). No early-return string compare.
+- Structured logs include `actor_role: 'patient'`, `actor_id: <redacted-phone last-4>` (matches E0-S3's redaction), and the four contract fields `request_id` / `actor_role` / `actor_id` / `appointment_id: null`. Phone numbers are redacted to last-4 in every log line.
+- `req.auth.claim` is never consulted by `/patient/otp/send` or `/patient/otp/verify` — the routes are unauthenticated (the OTP **is** the authentication). `x-auth-claim` debug header is never consulted either. Both routes mount BEFORE `authMiddleware` (mirroring E0-S3's mount order for `/patient/otp/verify-now`).
+- Routes are registered when `NODE_ENV ∈ {development, test, staging, production}` — the real OTP gateway is **never** dev-only. The mocked `LogSmsOtpProvider` is what dev/test use; the gateway itself runs in every env. (See A1 for the mock-verify-now disposition.)
+- Migration: `0012_sms_otp_send_attempts.sql` — adds a `last_sent_at timestamptz` column to `otp_verification` for the 30-second cooldown check (the existing `created_at` is not enough — a successful verify must NOT reset the cooldown, only a fresh send should; `last_sent_at` is the column that `send()` updates). Also adds `attempts` index for the locked-window lookup. Plus the existing down migration. Migration numbering starts at `0012` per W17.
+- Counter: `inc('otp.verification', 1)` fires on every verify attempt (success + failure) — matches the metrics contract from E0-S1 and is observable from `GET /metrics`.
+- Log redaction: `req.body.code` is already in `redactPaths` (E0-S1 contract). Phone numbers are redacted to last-4 in `info` audit logs. The full 6-digit OTP code is logged at `info` by `LogSmsOtpProvider` ONLY — production guard refuses to register `LogSmsOtpProvider` in production.

+- No plain-text OTP storage — every stored code is sha-256-hashed.

+ * SmsOtpProvider — the seam between the OTP service and the outside world.
+ *
+ * The service never imports a real SDK directly. Every implementation must
+ * conform to this interface so a stub (LogSmsOtpProvider, dev/test) and a
+ * real Twilio client (TwilioSmsOtpProvider, prod) can be swapped without
+ * touching the service code.
+ *
+ * Contract:
+ *   - `send()` is fire-and-forget from the caller's POV: a successful return
+ *     means the provider accepted the message; delivery failures are async
+ *     and out of scope (W22).
+ *   - `send()` MUST throw `SmsSendFailed` on synchronous failure (auth,

+/**
+ * SmsOtpService — the OTP subsystem's brain.
+ *
+ * Two entry points:
+ *   - `send(phone)`     — generate + persist + dispatch a 6-digit OTP
+ *   - `verify(phone, code)` — compare + commit
+ *
+ * The service is the SOLE writer to `otp_verification`. Routes call this
+ * class; nothing else inserts/updates/deletes rows in that table. (Test
+ * helpers may create fixtures but never with the live `code_hash` column.)
+ *
+ * Transactional contract:
+ *   - `send()` runs `BEGIN; DELETE expired; check cooldown/locked; INSERT;
+ *     provider.send(); COMMIT`. If the provider throws, the transaction
+ *     is rolled back and no orphan `otp_verification` row remains. The
+ *     caller surfaces 502 and the user retries. This is the AC-22
+ *     contract — provider failure is atomic with the DB write.
+ *
+ *   - `verify()` runs `BEGIN; SELECT FOR UPDATE; compare hash; on success
+ *     DELETE row + COMMIT + mint JWT; on failure UPDATE attempts (and
+ *     locked_until if threshold hit) + COMMIT + throw`. The `FOR UPDATE`
+ *     lock prevents two parallel verifies from both decrementing attempts.
+ *
+ * `code_hash` is `pgcrypto.digest(code, 'sha256')` — 64-char hex. We do
+ * NOT compute the hash in Node because then we'd be computing the same
+ * hash on every verify (defeating timing-safe comparison at the SQL level).
+ * Doing it in SQL keeps the contract symmetric: insert-side and verify-side
+ * both use the database's pgcrypto.
+ */
+import type pg from 'pg';
+import { randomInt, timingSafeEqual } from 'node:crypto';
+import { signClaim, verifyToken, type AuthClaim } from '../auth/jwt.js';
+import type { SmsOtpProvider } from './provider.js';
+import { SmsSendFailed } from './provider.js';
+import type { OtpConfig } from './config.js';
+import {
+  OtpCooldownError,
+  OtpLockedError,
+  OtpExpiredError,
+  NoOutstandingOtpError,
+  InvalidOtpCodeError,
+} from './errors.js';
+
+export interface SendResult {
+  expiresAt: Date;
+  cooldownMs: number;
+}
+
+export interface VerifyResult {
+  token: string;
+  claim: AuthClaim;
+  expiresAt: string;
+}
+
+interface OtpRow {
+  id: string;
+  phone_e164: string;
+  code_hash: string;
+  expires_at: Date;
+  attempts: number;
+  locked_until: Date | null;
+  last_sent_at: Date;
+  created_at: Date;
+}
+
+export class SmsOtpService {
+  private readonly pool: pg.Pool;
+  private readonly provider: SmsOtpProvider;
+  private readonly cfg: OtpConfig;
+
+  constructor(pool: pg.Pool, provider: SmsOtpProvider, cfg: OtpConfig) {
+    this.pool = pool;
+    this.provider = provider;
+    this.cfg = cfg;
+  }
+
+  /**
+   * Generate a 6-digit numeric code with uniform distribution via
+   * `crypto.randomInt`. `padStart` handles leading zeros (e.g. 0..99 → '000123').
+   */
+  private generateCode(): string {
+    const n = randomInt(0, 10 ** this.cfg.codeLength);
+    return String(n).padStart(this.cfg.codeLength, '0');
+  }
+
+  /**
+   * Compute `retryAfterMs` from a future Date. Defensive against clock skew
+   * (returns 0 if the date is already past).
+   */
+  private msUntil(when: Date | null): number {
+    if (!when) return 0;
+    const ms = when.getTime() - Date.now();
+    return ms > 0 ? ms : 0;
+  }
+
+  public async send(phone: string): Promise<SendResult> {
+    const code = this.generateCode();
+    const client = await this.pool.connect();
+    try {
+      await client.query('BEGIN');
+      // Step 1: cleanup any expired row for this phone. Plain UNIQUE on
+      // phone_e164 means at most one outstanding row ever; this delete is
+      // defense-in-depth so the INSERT never trips the unique constraint
+      // spuriously.
+      await client.query(
+        `DELETE FROM otp_verification WHERE phone_e164 = $1 AND expires_at < now()`,
+        [phone],
+      );
+      // Step 2: fetch the live row (if any) to evaluate cooldown + lockout.
+      const rowResult = await client.query<OtpRow>(
+        `SELECT id, phone_e164, code_hash, expires_at, attempts, locked_until, last_sent_at, created_at
+         FROM otp_verification WHERE phone_e164 = $1 FOR UPDATE`,
+        [phone],
+      );
+      const row = rowResult.rows[0];
+      const now = Date.now();
+      if (row) {
+        // Lockout takes precedence over cooldown: a locked phone stays
+        // locked even if the cooldown window has elapsed, until 10 minutes
+        // pass since the lockout was set.
+        if (row.locked_until && new Date(row.locked_until).getTime() > now) {
+          await client.query('COMMIT');
+          throw new OtpLockedError(this.msUntil(row.locked_until));
+        }
+        // Resend cooldown: 30s since the last send.
+        const lastSent = new Date(row.last_sent_at).getTime();
+        const cooldownMs = this.cfg.cooldownSeconds * 1000 - (now - lastSent);
+        if (cooldownMs > 0) {
+          await client.query('COMMIT');
+          throw new OtpCooldownError(cooldownMs);
+        }
+      }
+      // Step 3: insert (or replace) the row. The ON CONFLICT DO UPDATE path
+      // covers the case where a row exists but neither locked nor in
+      // cooldown — we rotate the code, attempts, locked_until, and reset
+      // created_at / last_sent_at.
+      const codeHashResult = await client.query<{ code_hash: string }>(
+        `SELECT pgcrypto.digest($1, 'sha256')::text AS code_hash`,
+        [code],
+      );
+      const codeHash = codeHashResult.rows[0]!.code_hash;
+      const expiresAt = new Date(now + this.cfg.ttlSeconds * 1000);
+      const insertResult = await client.query<{ expires_at: Date }>(
+        `INSERT INTO otp_verification (phone_e164, code_hash, expires_at, attempts, locked_until, last_sent_at, created_at)
+         VALUES ($1, $2, $3, 0, NULL, app_now(), app_now())
+         ON CONFLICT (phone_e164) DO UPDATE SET
+           code_hash = EXCLUDED.code_hash,
+           expires_at = EXCLUDED.expires_at,
+           attempts = 0,
+           locked_until = NULL,
+           last_sent_at = EXCLUDED.last_sent_at,
+           created_at = EXCLUDED.created_at
+         RETURNING expires_at`,
+        [phone, codeHash, expiresAt],
+      );
+      const newExpiresAt = insertResult.rows[0]!.expires_at;
+      // Step 4: dispatch via the provider BEFORE committing so a provider
+      // failure rolls back the INSERT and no orphan row remains. The user
+      // then retries after the cooldown; the new send supersedes nothing.
+      try {
+        await this.provider.send(phone, code);
+      } catch (err) {
+        await client.query('ROLLBACK').catch(() => undefined);
+        if (err instanceof SmsSendFailed) throw err;
+        throw new SmsSendFailed('provider_threw_unknown', err);
+      }
+      await client.query('COMMIT');
+      return {
+        expiresAt: newExpiresAt,
+        cooldownMs: this.cfg.cooldownSeconds * 1000,
+      };
+    } catch (err) {
+      // If we already committed, the rollback is a no-op; pg ignores it.
+      await client.query('ROLLBACK').catch(() => undefined);
+      throw err;
+    } finally {
+      client.release();
+    }
+  }
+
+  public async verify(phone: string, code: string): Promise<VerifyResult> {
+    const client = await this.pool.connect();
+    try {
+      await client.query('BEGIN');
+      const rowResult = await client.query<OtpRow>(
+        `SELECT id, phone_e164, code_hash, expires_at, attempts, locked_until, last_sent_at, created_at
+         FROM otp_verification WHERE phone_e164 = $1 FOR UPDATE`,
+        [phone],
+      );
+      const row = rowResult.rows[0];
+      const now = Date.now();
+      if (!row) {
+        await client.query('COMMIT');
+        throw new NoOutstandingOtpError();
+      }
+      if (row.locked_until && new Date(row.locked_until).getTime() > now) {
+        // Locked: do NOT increment attempts. The lockout window is a hard
+        // stop until it expires; counting failures during the lockout
+        // would extend the window unpredictably.
+        await client.query('COMMIT');
+        throw new OtpLockedError(this.msUntil(row.locked_until));
+      }
+      if (new Date(row.expires_at).getTime() <= now) {
+        await client.query('COMMIT');
+        throw new OtpExpiredError();
+      }
+      // Compute the hash of the input via the DB so we compare against the
+      // same digest the service stored. Doing the hash in Node would be
+      // equivalent in correctness but loses the SQL-side symmetry that
+      // makes the contract self-documenting.
+      const inputHashResult = await client.query<{ code_hash: string }>(
+        `SELECT pgcrypto.digest($1, 'sha256')::text AS code_hash`,
+        [code],
+      );
+      const inputHash = inputHashResult.rows[0]!.code_hash;
+      // timingSafeEqual on equal-length buffers. Both are 64-char hex
+      // (sha-256); lengths are guaranteed identical.
+      const a = Buffer.from(row.code_hash, 'utf8');
+      const b = Buffer.from(inputHash, 'utf8');
+      const matches = a.length === b.length && timingSafeEqual(a, b);
+      if (!matches) {
+        const newAttempts = row.attempts + 1;
+        const hitThreshold = newAttempts >= this.cfg.lockoutThreshold;
+        if (hitThreshold) {
+          const lockedUntil = new Date(now + this.cfg.lockoutSeconds * 1000);
+          await client.query(
+            `UPDATE otp_verification SET attempts = $2, locked_until = $3 WHERE id = $1`,
+            [row.id, newAttempts, lockedUntil],
+          );
+        } else {
+          await client.query(
+            `UPDATE otp_verification SET attempts = $2 WHERE id = $1`,
+            [row.id, newAttempts],
+          );
+        }
+        await client.query('COMMIT');
+        throw new InvalidOtpCodeError();
+      }
+      // Success path: delete the row in the same transaction, mint the
+      // JWT, and return. The JWT minting is intentionally outside the
+      // transaction's lock window — the row is already gone from the DB
+      // before we hand the token to the caller.
+      await client.query(`DELETE FROM otp_verification WHERE id = $1`, [row.id]);
+      await client.query('COMMIT');
+      const token = signClaim({
+        sub: phone,
+        role: 'patient',
+        branch_ids: [],
+        scope: 'self',
+      });
+      const claim = verifyToken(token);
+      if (!claim) {
+        // Unreachable: we just signed it with our own verifier's rules.
+        throw new Error('sms_otp_mint_failed_internal');
+      }
+      const expiresAt = new Date(claim.expires_at * 1000).toISOString();
+      return { token, claim, expiresAt };
+    } catch (err) {
+      await client.query('ROLLBACK').catch(() => undefined);
+      throw err;
+    } finally {
+      client.release();
+    }
+  }
+}

+/**
+ * SMS OTP routes — `/patient/otp/send` and `/patient/otp/verify`.
+ *
+ * Both routes are unauthenticated (the OTP is the credential). They mount
+ * BEFORE `authMiddleware` so a patient who has not yet verified can hit
+ * them. They NEVER consult `req.auth.claim` or `req.body.role` /
+ * `req.body.branch_ids` / `req.body.scope` / `req.body.doctor_id`.
+ *
+ * Phone is E.164-validated (`^\+[1-9]\d{6,14}$`). Code is 6-digit numeric.
+ * Validation errors return 400 BEFORE consulting the service so a bad
+ * input never increments `attempts`.
+ *
+ * The verify path produces the same `{token, claim, expires_at}` shape as
+ * E0-S3's `/patient/otp/verify-now`, so E4-S1 can swap its body without
+ * touching the response contract.
+ */
+import { Router, type Request, type Response, type RequestHandler } from 'express';
+import { getLogger } from '../middleware/log.js';
+import type { SmsOtpService } from '../otp/service.js';
+import {
+  OtpCooldownError,
+  OtpLockedError,
+  OtpExpiredError,
+  NoOutstandingOtpError,
+  InvalidOtpCodeError,
+} from '../otp/errors.js';
+import { SmsSendFailed } from '../otp/provider.js';
+import { inc } from '../metrics/counters.js';
+
+const E164_REGEX = /^\+[1-9]\d{6,14}$/;
+const CODE_REGEX = /^\d{6}$/;
+
+function redactPhone(phone: string): string {
+  if (phone.length <= 4) return '****';
+  return `***${phone.slice(-4)}`;
+}
+
+export interface SmsOtpRouterDeps {
+  service: SmsOtpService;
+}
+
+export function createSmsOtpRouter(deps: SmsOtpRouterDeps): Router {
+  const router = Router();
+
+  router.post('/otp/send', (async (req: Request, res: Response): Promise<void> => {
+    const body = (req.body ?? {}) as Record<string, unknown>;
+    if (typeof body['phone'] !== 'string' || !E164_REGEX.test(body['phone'])) {
+      getLogger().info(
+        { event: 'sms_otp_send', outcome: 'invalid_phone', phone: redactPhone(String(body['phone'] ?? '')) },
+        'sms_otp_send_rejected',
+      );
+      res.status(400).json({ error: 'invalid_phone' });
+      return;
+    }
+    const phone = body['phone'] as string;
+    try {
+      const result = await deps.service.send(phone);
+      getLogger().info(
+        { event: 'sms_otp_send', outcome: 'success', phone: redactPhone(phone) },
+        'sms_otp_send_success',
+      );
+      res.status(200).json({
+        expires_at: result.expiresAt.toISOString(),
+        cooldown_ms: result.cooldownMs,
+      });
+    } catch (err) {
+      if (err instanceof OtpCooldownError) {
+        getLogger().info(
+          { event: 'sms_otp_send', outcome: 'cooldown', phone: redactPhone(phone), retry_after_ms: err.retryAfterMs },
+          'sms_otp_send_rejected',
+        );
+        res.status(429).json({ error: 'otp_cooldown', retry_after_ms: err.retryAfterMs });
+        return;
+      }
+      if (err instanceof OtpLockedError) {
+        getLogger().info(
+          { event: 'sms_otp_send', outcome: 'locked', phone: redactPhone(phone), retry_after_ms: err.retryAfterMs },
+          'sms_otp_send_rejected',
+        );
+        res.status(429).json({ error: 'otp_locked', retry_after_ms: err.retryAfterMs });
+        return;
+      }
+      if (err instanceof SmsSendFailed) {
+        getLogger().warn(
+          { event: 'sms_otp_send', outcome: 'provider_failure', phone: redactPhone(phone), err: err.message },
+          'sms_otp_send_failed',
+        );
+        res.status(502).json({ error: 'sms_send_failed' });
+        return;
+      }
+      throw err;
+    }
+  }) as RequestHandler);
+
+  router.post('/otp/verify', (async (req: Request, res: Response): Promise<void> => {
+    const body = (req.body ?? {}) as Record<string, unknown>;
+    if (typeof body['phone'] !== 'string' || !E164_REGEX.test(body['phone'])) {
+      getLogger().info(
+        { event: 'sms_otp_verify', outcome: 'invalid_phone', phone: redactPhone(String(body['phone'] ?? '')) },
+        'sms_otp_verify_rejected',
+      );
+      res.status(400).json({ error: 'invalid_phone' });
+      return;
+    }
+    if (typeof body['code'] !== 'string' || !CODE_REGEX.test(body['code'])) {
+      getLogger().info(
+        { event: 'sms_otp_verify', outcome: 'invalid_code', phone: redactPhone(body['phone'] as string) },
+        'sms_otp_verify_rejected',
+      );
+      res.status(400).json({ error: 'invalid_code' });
+      return;
+    }
+    const phone = body['phone'] as string;
+    const code = body['code'] as string;
+    try {
+      // Increment on EVERY verify attempt (success + failure + expired +
+      // locked + no-row) — matches the E0-S1 metrics contract and the
+      // E7-S9 (product metrics) success-rate calculation.
+      inc('otp.verification');
+      const result = await deps.service.verify(phone, code);
+      getLogger().info(
+        { event: 'sms_otp_verify', outcome: 'success', phone: redactPhone(phone) },
+        'sms_otp_verify_success',
+      );
+      res.status(200).json({
+        token: result.token,
+        claim: result.claim,
+        expires_at: result.expiresAt,
+      });
+    } catch (err) {
+      if (err instanceof NoOutstandingOtpError) {
+        getLogger().info(
+          { event: 'sms_otp_verify', outcome: 'no_row', phone: redactPhone(phone) },
+          'sms_otp_verify_rejected',
+        );
+        res.status(401).json({ error: 'no_outstanding_otp' });
+        return;
+      }
+      if (err instanceof OtpExpiredError) {
+        getLogger().info(
+          { event: 'sms_otp_verify', outcome: 'expired', phone: redactPhone(phone) },
+          'sms_otp_verify_rejected',
+        );
+        res.status(401).json({ error: 'otp_expired' });
+        return;
+      }
+      if (err instanceof OtpLockedError) {
+        getLogger().info(
+          { event: 'sms_otp_verify', outcome: 'locked', phone: redactPhone(phone), retry_after_ms: err.retryAfterMs },
+          'sms_otp_verify_rejected',
+        );
+        res.status(429).json({ error: 'otp_locked', retry_after_ms: err.retryAfterMs });
+        return;
+      }
+      if (err instanceof InvalidOtpCodeError) {
+        getLogger().info(
+          { event: 'sms_otp_verify', outcome: 'wrong_code', phone: redactPhone(phone) },
+          'sms_otp_verify_rejected',
+        );
+        res.status(401).json({ error: 'invalid_otp_code' });
+        return;
+      }
+      throw err;
+    }
+  }) as RequestHandler);
+

+  const logLine = [...lines].reverse().find(

+  if (!logLine) return null;
+  const obj = JSON.parse(logLine) as { code?: string; phone?: string };
+  if (obj.phone !== '***' + phone.slice(-4)) return null;
+  return typeof obj.code === 'string' ? obj.code : null;
